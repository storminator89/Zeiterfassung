# Laravel LDAP Admin mount — source only

This slice mounts the previously reviewed LDAP orchestration and form/result contracts into the existing Admin page. It is **not** a running LDAP installation, a directory/key admission, a Native cutover, or a claim of end-to-end acceptance.

The local prerequisite commit `acb3cf772bc87a1b06d7b86e4efaad28d315b330` (tree `eec84e5d515b94ed4502a3806bc7c953be41c342`) combines unchanged Gate/UI12 `b738400180d7bf42f246d1839c13a330c9044752` with Form5 `f8c8536ec8322e33c4afe30307bc39e2eacda548`. Exactly sixteen paths: existing Admin controller, two view DTOs, AppServiceProvider, LocalWebRoutes, Admin and app Blade files; new fixed document-policy helper, LDAP-only stock throttle wrapper, default-false technical HTTP config, two local Blade partials, three LDAP language files, and this document. No Writer, core policy, admission, native LDAP, settings, fixtures, setup/token, Home controller or `home-ui.md` change. External PR #197 and any Native/runtime holds remain intact.

## Authorization and opt-ins

* Existing registrar flags remain unchanged; new `includeLdapSync=false` requires Admin opt-in, explicit admitted writable V4 mode, `app.debug === false`, and stock persistent file cache. The technical HTTP flag is set only by this trusted registrar, not by form/environment data.
* The stored LDAP intake flag is mandatory, independent of the technical opt-in. Fresh local Admin/password-version/policy checks occur before lazy collector/key resolution; exact policy revision and local identity are rechecked under the existing Writer lock. Changing policy alone does not start a sync or install a connector.
* Provider construction is pure/lazy. No default host, CA, cipher root, key loader, fallback root creation, directory connection, account, scheduler or automatic sync is provided. A trusted separately admitted `LdapSyncTransport` and `AdmittedLdapSettingsCipher` binding are required. The collector's immutable target/CA and native cipher contract remain those reviewed in the transport slice.
* If LDAP is off, GET calls no collector/cipher factory. The policy card remains available even with all three intake methods off. A policy-off race during target lookup is distinguished by a fresh policy/Admin reload; Admin revocation is never swallowed as connector unavailability.
* Only the six original LDAP form fields plus the two existing CSRF aliases are accepted, as one unmixed command. Existing raw-form trimming exemptions preserve password bytes. The route remains inside the existing encrypted-session, CSRF, refreshed-local-account and auth.session stack; no CSRF exemption is introduced. `bootstrap/app.php` already excludes `ldap_pass` from flashed input and sanitizes exception logging; it is unchanged.
* LDAP POST additionally uses standard Laravel throttle counters in the current explicit file cache: 5 attempts per ten minutes per authenticated ID and 20 per hour per IP. Middleware is reconstructed against the current store, avoiding a lost named-limiter definition after cache rebind. Other Admin commands do not consume these limits. Session locking remains mandatory. This is stock persistent throttling, not a claim of cross-node/global admission control.

## Credential document and outcome

Every V4 Admin document, including all-off recovery, requires non-debug composition and receives no-store, no-referrer, nosniff, frame denial and an appended restrictive CSP. Each rendered document receives a fresh nonce for its existing inline scripts; inline event handlers are replaced by nonce-script listeners only on this branch. No external CSS/font links are emitted on that branch. Existing local CSS plus a bounded local card/control/icon fallback preserve the existing markup without downloading vendor assets. Local CSS contains no imports or URLs. Script, image, font and fetch sources are same-origin only; there is no unsafe-inline script allowance. CSP headers intersect with any pre-existing stricter policy rather than replacing it.

Legacy V2/V3 pages retain the original asset/handler branch and cannot dispatch the new LDAP command. Local font/icon fallback is not pixel-identical to the remote theme; mobile/browser visual acceptance is still required in a separately authorized environment. No browser, server or actual HTTP flow is asserted here.

The form contains only the server-confirmed read-only target plus blank bind DN/password fields. Neither uses old input or an existing LDAP settings row. The controller never renders a posted credential on failure. Errors are fixed plain no-store responses; unexpected outcomes are explicitly unconfirmed, not a rollback or retry instruction. Once the service returns after commit, any presentation/flash failure is also unconfirmed. Successful PRG is 303; the one-use result flash contains only the current actor ID and the bounded allowlisted outcome (at most twenty account-ID/reason details), never the native plan, assignments, bind data, ciphertext or password hash. The next fresh Admin page validates actor binding and shape before display.
